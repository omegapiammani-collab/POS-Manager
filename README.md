# POS Manager

ระบบ POS สำหรับพัฒนาในเครื่อง ใช้ Python 3.10 ขึ้นไปและ SQLite

```sh
python3 -m unittest -v
python3 inventory_api.py
```

เปิดหน้าเว็บที่ `http://127.0.0.1:8000` และเก็บข้อมูลใน `inventory.sqlite3`
ใช้ `--database` เพื่อเปิดไฟล์ฐานข้อมูล POS ที่มีอยู่แล้ว และ `--port` เพื่อเปลี่ยนพอร์ต หากต้องการสร้างฐานข้อมูลใหม่โดยตั้งชื่อเอง ให้ใช้ `python3 inventory_api.py --database my-store.sqlite3 --create-database` คำสั่งสร้างใหม่จะไม่เขียนทับไฟล์เดิม ส่วนการเรียกโดยไม่ระบุ `--database` จะสร้าง `inventory.sqlite3` เมื่อยังไม่มีไฟล์นี้

| วิธี | เส้นทาง | ข้อมูล |
| --- | --- | --- |
| GET | `/products?q=W01` | ค้นชื่อหรือรหัส แสดงหน่วยขาย ยอดคงเหลือ ต้นทุนเฉลี่ย และสถานะสินค้าใกล้หมด |
| POST | `/products` | `code`, `name`, `base_unit`, `price`, `minimum_quantity` (ไม่บังคับ) |
| POST | `/products/{id}/units` | `name`, `multiplier`, `price` |
| POST | `/products/{id}/receipts` | `unit_id`, `quantity`, `unit_cost` |
| GET | `/products/{id}/receipts` | ประวัติรับสินค้า เรียงจากรายการล่าสุด |

ส่งข้อมูล POST ด้วย `Content-Type: application/json` ต้นทุนรับเข้าเป็นราคาทุนต่อหน่วยที่เลือก
เช่น รับน้ำดื่ม 1 แพ็ก ราคาทุนแพ็กละ 120 บาท ให้ส่ง `quantity` เป็น 1 และ `unit_cost` เป็น 120
หากแพ็กมี 12 ขวด ระบบเพิ่มสต๊อก 12 ขวดในหน่วยสต๊อก

การซิงก์หลายอุปกรณ์และบัญชีเจ้าของร้านอยู่ในแผนงานถัดไป

เซิร์ฟเวอร์กำหนดรหัสร้านและรหัสผูกคิว อ่านได้จาก `GET /store-identity` หน้าขายผูกคิวและแคชกับ `binding_id` และเซิร์ฟเวอร์ตรวจรหัสผูกใน transaction ก่อนรับบิลหรือยกเลิกบิลค้าง หากรหัสไม่ตรงระบบจะหยุดและเก็บคิวไว้ บิลค้างรุ่นเก่าที่ไม่มีรหัสต้องตรวจสอบและยืนยันร้านด้วยตนเองก่อนส่ง ขณะออฟไลน์ต้องเคยยืนยันรหัสผูกในเครื่องมาก่อนจึงปิดบิลได้

คำสั่ง `database_backup.py restore` คงรหัสร้านเดิม แต่สร้างรหัสผูกใหม่ในไฟล์ปลายทางโดยไม่แก้ไฟล์สำรอง หน้าขายที่พบการกู้คืนจะหยุดส่งคิว ให้เจ้าของยืนยัน และเปลี่ยนบิล pending เป็นต้องตรวจสอบก่อนส่ง ต้องตรวจประวัติบิลและการรับเงินจากแหล่งข้อมูลอื่น เพราะฐานเก่าอาจไม่มีบิลหรือบันทึกยกเลิกหลังวันสำรอง การคัดลอกหรือเขียนทับไฟล์ด้วยวิธีภายนอกที่คงรหัสผูกเดิม รวมถึงสำเนาที่แตกแขนง อาจตรวจไม่พบ รหัสเหล่านี้ไม่ใช่การยืนยันตัวตน ควรสำรองฐานข้อมูลและคิวก่อนสลับหรือกู้คืนข้อมูล

ไฟล์หน้าขายและไฟล์ประกอบถูกอ่านเป็นชุดเมื่อเริ่มเซิร์ฟเวอร์ เซิร์ฟเวอร์ตรวจ checksum จาก `web/shell-manifest.json` และไม่เริ่มหากไฟล์ไม่ตรง หลังแก้ไฟล์หน้าขายให้รัน `python3 shell_manifest.py` แล้วเก็บ manifest พร้อมไฟล์ที่แก้ใน repository ก่อนติดตั้งทั้งชุดและเริ่มเซิร์ฟเวอร์ใหม่ ใช้ `python3 shell_manifest.py --check` เพื่อตรวจ manifest โดยไม่แก้ไฟล์ เบราว์เซอร์ที่ยังใช้ service worker รุ่นเก่าอาจต้องปิดแท็บ POS ทั้งหมดและเปิดใหม่เพื่อรับชุดออฟไลน์รุ่นใหม่; worker รุ่นเก่าที่ยังค้างอยู่ยังมีพฤติกรรมแคชเดิมจนกว่าจะอัปเกรด

ถ้าไฟล์หน้าจอในแคชหาย ระบบหยุดโหลดไฟล์นั้นเพื่อหลีกเลี่ยงการใช้ไฟล์คนละรุ่น และแสดงคำเตือนเมื่อทำได้ อย่าลบข้อมูลเว็บไซต์เพื่อแก้ปัญหานี้ เพราะอาจลบบิลที่รอส่งในเครื่อง ให้ติดต่อผู้ดูแลเพื่อตรวจสอบและสำรองคิวก่อนดำเนินการ

โปรแกรมภายนอกที่ส่ง `POST /sales`, `POST /offline-sales`, `POST /sales/allow-negative` หรือ `POST /sales/{id}/abandon` ต้องส่ง header `X-POS-Store-ID` ตรงกับ `binding_id` ปัจจุบัน หากไม่มีหรือไม่ตรง เซิร์ฟเวอร์ปฏิเสธคำขอ รหัสร้าน (`id`) ยังเหมือนเดิมหลัง restore แต่ไม่ใช่ค่าที่ใช้แทน `binding_id` หลัง restore

หลังอัปเดตให้ปิดแท็บ POS เก่าและเปิดหน้าขายใหม่ขณะออนไลน์ เพื่อเตรียมหน้าสำหรับออฟไลน์และตรวจสอบรหัสร้านก่อนใช้งาน หน้าขายรุ่นเก่าที่ไม่ส่งรหัสร้านจะไม่สามารถส่งบิลเข้าเซิร์ฟเวอร์รุ่นนี้ได้

## แก้ไขข้อมูลสินค้าและราคาขาย

เลือกสินค้าจากหน้า **สินค้าและสต๊อก** แล้วแก้ไขรหัส ชื่อ หรือจำนวนขั้นต่ำที่ใช้แจ้งเตือน
ใช้ตัวกรองเพื่อดูสินค้าใกล้หมด สต๊อกติดลบ หรือสินค้าพักขายร่วมกับคำค้นได้
รายการใกล้หมดแสดงเฉพาะสินค้าที่เปิดขายและมีสต๊อกตั้งแต่ศูนย์ขึ้นไป ส่วนรายการสต๊อกติดลบรวมสินค้าพักขายด้วย
กด **ดาวน์โหลดรายการสต๊อก CSV** เพื่อบันทึกสินค้าที่ตรงกับตัวกรองและคำค้น พร้อมจำนวนคงเหลือและต้นทุนเฉลี่ย
เลือก **พักขาย** เพื่อซ่อนสินค้าจากหน้าขาย หรือ **เปิดขายอีกครั้ง** เพื่อนำกลับมาขาย
การพักขายคงสต๊อกและประวัติไว้ บิลออฟไลน์ที่มีเวลาขายยังส่งเข้าระบบได้
ปรับราคาขายได้แยกตามหน่วยขาย บิลที่บันทึกแล้วแสดงชื่อและราคาที่บันทึกตอนขาย
หากอีกเครื่องแก้ข้อมูลเดียวกันก่อน ให้ตรวจข้อมูลล่าสุดก่อนบันทึกอีกครั้ง
บิลออฟไลน์ที่บันทึกเวลาขายแล้วใช้ราคาที่ปิดบิล ส่วนการขายออนไลน์ตรวจราคาปัจจุบันก่อนบันทึก

## ปรับยอดจากการตรวจนับ

ที่หน้า **สินค้าและสต๊อก** เลือกสินค้าแล้วกด **ปรับยอดจากการตรวจนับ**
กรอกจำนวนที่พบจริงเป็นหน่วยสต๊อกของสินค้าและระบุเหตุผล
ระบบเก็บยอดก่อนปรับ ยอดที่นับได้ ผลต่าง และต้นทุนที่ใช้ปรับในประวัติ
ถ้ายอดสต๊อกเปลี่ยนระหว่างตรวจนับ ให้ตรวจจำนวนอีกครั้งก่อนส่งรายการใหม่

เมื่อยอดเพิ่ม ระบบใช้ต้นทุนต่อหน่วยที่กรอก หรือต้นทุนเฉลี่ยล่าสุดหากเว้นว่าง
สินค้าที่ยังไม่มีต้นทุนเฉลี่ยต้องระบุต้นทุนก่อนปรับเพิ่ม
การปรับลดจำนวนคงต้นทุนเฉลี่ยต่อหน่วยเดิม
เมื่อปรับยอดติดลบให้ตรงกับจำนวนที่นับได้ ระบบจัดสรรต้นทุนที่ใช้ตรวจนับให้บิลที่ขาดตามลำดับ
ประวัติบิลระบุว่าต้นทุนส่วนนี้มาจากการปรับยอดจากการตรวจนับ

## หน้าขาย

เปิด `http://127.0.0.1:8000/checkout` หลังเพิ่มสินค้าและบันทึกรับเข้า
เลือกสินค้าและหน่วยขาย แล้วแบ่งชำระด้วยเงินสด โอน หรือเงินเชื่อในบิลเดียว
ที่ช่องค้นหาสินค้า พิมพ์หรือสแกนรหัสสินค้าที่ตรงกันแล้วกด Enter เพื่อเพิ่มสินค้า 1 หน่วยพื้นฐาน ทำซ้ำเพื่อเพิ่มจำนวนได้
เมื่อมีเงินเชื่อให้เลือกหรือเพิ่มชื่อลูกค้า จากนั้นเลือกพิมพ์หรือข้ามใบเสร็จได้
เมื่อรับเงินสด สามารถกรอกเงินสดที่รับเพื่อคำนวณเงินทอน ยอดเงินสดในบิลยังเป็นยอดที่นำมาชำระสินค้า

### QR พร้อมเพย์ตามยอดโอน

ติดตั้งไลบรารีสร้าง QR ด้วย `python3 -m pip install -r requirements-qr.txt`
แล้วกำหนดตัวแปรสภาพแวดล้อม `POS_PROMPTPAY_MOBILE` เป็นเบอร์มือถือ 10 หลัก
ที่ผูกพร้อมเพย์ของร้าน และกำหนด `POS_PROMPTPAY_NAME` เป็นชื่อร้านภาษาอังกฤษ
ความยาวไม่เกิน 25 อักขระ ก่อนเริ่มเซิร์ฟเวอร์

ระบบใส่เฉพาะยอดส่วนที่โอนใน QR เจ้าของร้านตรวจเงินเข้าด้วยตนเองก่อนยืนยัน
ก่อนเริ่มใช้งานจริง ให้สแกนตรวจสอบชื่อผู้รับและยอดที่แอปธนาคารแสดง

โครงสร้างข้อมูลอ้างอิงจาก [มาตรฐาน Thai QR Payment ของ ธปท.](https://www.bot.or.th/content/dam/bot/documents/th/our-roles/payment-systems/about-payment-systems/ThaiQRCode_Payment_Standard.pdf)

## ลูกหนี้

เปิด `http://127.0.0.1:8000/debts` หรือเลือก **ลูกหนี้** จากเมนู
เลือกชื่อลูกค้าเพื่อดูยอดค้าง บิลเงินเชื่อ และประวัติรับชำระ
เมื่อรับเงินสดหรือโอน ให้กรอกยอดที่ได้รับและเลือกวิธีชำระ
ระบบตัดยอดจากบิลเก่าที่สุดก่อน และแสดงว่าเงินถูกนำไปตัดบิลใดบ้าง

ยอดรับชำระต้องไม่เกินยอดค้างรวมของลูกค้า หากเป็นเงินโอนให้ตรวจเงินเข้าก่อนบันทึก
เมื่อขาดการเชื่อมต่อระหว่างบันทึก ให้ใช้ปุ่มส่งรายการเดิมอีกครั้ง
ระบบใช้รหัสรายการเดิมเพื่อป้องกันการบันทึกรับเงินซ้ำ

## ประวัติบิล

เปิด `http://127.0.0.1:8000/bills` หรือเลือก **ประวัติบิล** จากเมนู
ค้นด้วยเลขอ้างอิงหรือชื่อลูกค้าร่วมกับช่วงวันที่และสถานะบิลได้ ระบุวันที่ด้านเดียวเพื่อกรองเฉพาะวันเริ่มต้นหรือวันสิ้นสุด
ช่วงวันที่นับรวมทั้งสองวันตามเวลาขายในประเทศไทย รวมถึงบิลออฟไลน์ที่ส่งเข้าระบบภายหลัง
กรองตามวิธีชำระเงินได้ด้วย ตัวกรองเงินสด โอนผ่าน QR และเงินเชื่อรวมบิลที่มียอดในวิธีนั้น
เลือก **ชำระหลายวิธี** เพื่อดูเฉพาะบิลที่มียอดตั้งแต่สองวิธีขึ้นไป
กด **ดาวน์โหลด CSV** เพื่อเก็บบิลที่ตรงกับตัวกรอง โดยไฟล์แสดงวันที่ขายตามเวลาไทย สถานะ ยอดแยกตามวิธีชำระ และเลขบิลทดแทนเมื่อมีการแก้ไข

เลือกบิลแล้วกด **พิมพ์ใบเสร็จ** เพื่อดูตัวอย่าง จากนั้นเลือกพิมพ์หรือปิดได้
ใบเสร็จย้อนหลังแสดงรายการ ราคา และยอดแยกตามวิธีชำระที่บันทึกตอนขาย พร้อมระบุสถานะของบิลที่ยกเลิก

เลือกบิลแล้วระบุเหตุผลเพื่อแก้ไขหรือยกเลิก ระบบเก็บบิลเดิมและคืนจำนวนสินค้าเข้าสต๊อก
เมื่อแก้ไข ระบบสร้างบิลทดแทนและตัดสต๊อกตามรายการใหม่ในคราวเดียวกัน

หากบิลเงินเชื่อเคยรับชำระ ระบบนำยอดที่รับแล้วไปตัดยอดเงินเชื่อของบิลทดแทนสำหรับลูกค้าคนเดิมก่อน
เมื่อมียอดชำระเกิน ให้เลือกบันทึกการคืนเงินจริงด้วยเงินสดหรือเงินโอน
หรือนำยอดทั้งหมดไปหักบิลค้างอื่นของลูกค้า โดยเริ่มจากบิลเก่าที่สุด
เจ้าของร้านเป็นผู้ตรวจสอบและดำเนินการรับหรือคืนเงินจริง

## ขายออฟไลน์ในหน้าขาย

เปิดหน้าขายขณะที่เชื่อมต่อเซิร์ฟเวอร์และรอให้ระบบเตรียมข้อมูลบนเบราว์เซอร์แต่ละเครื่อง
หลังจากนั้นหน้าขายใช้รายการสินค้าและลูกค้าจากข้อมูลที่เก็บไว้บนเครื่องได้
บิลที่ยังส่งไม่สำเร็จแสดงในรายการรอส่ง เมื่อเชื่อมต่อใหม่ให้เปิดหน้าขาย
เพื่อให้ระบบลองส่ง หรือกดปุ่มส่งบิลด้วยตนเอง ระบบใช้เลขอ้างอิงเดิมเพื่อป้องกันการตัดสต๊อกซ้ำ
ขณะเปิดหน้าขายและเบราว์เซอร์ออนไลน์ ระบบลองส่งบิลรอส่งเป็นระยะเมื่อเซิร์ฟเวอร์กลับมาทำงาน

ขณะออฟไลน์ ระบบยังสร้าง QR ระบุยอดและเพิ่มลูกค้าใหม่ไม่ได้
ใช้ QR ของร้านเมื่อต้องรับโอนและตรวจเงินเข้าก่อนยืนยัน
บิลที่ปิดขณะหน้าขายแสดงว่าออฟไลน์จะส่งผ่านเส้นทางสำหรับบิลออฟไลน์
หากบิลออนไลน์มีสินค้าไม่พอ บิลจะอยู่ในคิวตรวจสอบ เจ้าของร้านสามารถตรวจรายการและยอดชำระ แล้วเลือกยืนยันขายแม้สต๊อกติดลบได้ ระบบจะตรวจราคาปัจจุบันและสถานะสินค้าก่อนบันทึก หากยังไม่ทราบผลให้ตรวจบิลและยืนยันส่งคำขอเดิมอีกครั้ง
หากบิลที่ต้องตรวจสอบไม่สามารถส่งต่อได้ สามารถยืนยันยกเลิกบิลค้างขณะเชื่อมต่อเซิร์ฟเวอร์ ระบบจะป้องกันไม่ให้บิลเลขเดิมถูกบันทึกภายหลัง และจะไม่ยกเลิกบิลที่บันทึกแล้ว ให้ตรวจสอบการรับเงินหรือคืนเงินกับลูกค้าด้วยตนเอง
ในคิวบิลกด **ดูรายละเอียด** เพื่อตรวจรายการ ราคาที่บันทึก ยอดชำระ ลูกค้า และเวลาขายที่มีอยู่ ชื่อสินค้า หน่วยขาย และลูกค้าใช้ข้อมูลล่าสุดที่เครื่องโหลดไว้ จึงอาจเปลี่ยนหลังขาย และบิลบางรายการไม่มีเวลาขายบันทึกไว้
ถ้าขายชนกับบิลอื่น ระบบเก็บทั้งสองบิลและแสดงสต๊อกติดลบที่หน้าสินค้าและสต๊อก
เมื่อรับสินค้าเข้า ระบบใช้ต้นทุนรับจริงจัดสรรให้จำนวนที่ขายเกินตามลำดับที่บันทึกบิลเข้าเซิร์ฟเวอร์
และแสดงต้นทุนที่จัดสรรแล้วในประวัติบิล สินค้าส่วนที่เหลือหลังจัดสรรจะเป็นสต๊อกพร้อมขาย
บิลออฟไลน์ที่มีเวลาขายเก็บราคาที่ปิดบิล แม้ร้านปรับราคาก่อนซิงก์
บิลเก่าที่ไม่มีเวลาขายยังตรวจราคาปัจจุบัน หากตรวจสินค้า หน่วยขาย หรือยอดชำระไม่ผ่าน บิลจะอยู่ในคิวตรวจสอบ
รายการที่ยังรอส่งอยู่กับเบราว์เซอร์เครื่องนั้น การล้างข้อมูลเว็บไซต์อาจลบรายการดังกล่าว
หน้าขายแสดงสถานะการเก็บข้อมูลถาวร และมีปุ่มขออนุญาตจากเบราว์เซอร์เมื่อรองรับ
หากไม่ได้รับอนุญาตยังขายได้ตามปกติ และสามารถสำรองบิลรอส่งจากหน้าสำรองข้อมูล
ตั้งนาฬิกาของเครื่องให้ถูกต้องก่อนขายออฟไลน์ เพราะระบบใช้เวลาจากเครื่องตอนปิดบิล

## ค่าใช้จ่ายร้าน

เปิด `http://127.0.0.1:8000/expense-entry` หรือเลือก **ค่าใช้จ่าย** จากเมนู
ระบุวันที่ รายการ และยอดเงิน แล้วเลือกว่าจ่ายจากลิ้นชักหรือจ่ายจากช่องทางอื่น
หากกรอกผิด ให้ยกเลิกพร้อมเหตุผลแล้วบันทึกรายการใหม่ รายการเดิมยังอยู่ในประวัติ

รายงานรายวันและตามช่วงวันที่รวมค่าใช้จ่ายทั้งสองแหล่ง และแสดงกำไรหลังหักค่าใช้จ่ายที่บันทึกไว้
ค่าใช้จ่ายของวันที่ไม่มีการขายยังอยู่ในรายงาน กำไรรายสินค้าคำนวณเป็นกำไรขั้นต้น

## รายงานยอดขาย

เปิด `http://127.0.0.1:8000/reports` แล้วเลือกวันเริ่มต้นและวันสิ้นสุดตามเวลาไทย
รายงานแสดงยอดขาย เงินสด เงินโอน เงินเชื่อ ต้นทุน และกำไรขั้นต้น
พร้อมรายละเอียดรายวันและรายสินค้า

บิลที่แก้ไขใช้ยอดบิลทดแทนในวันของบิลเดิม บิลที่ยกเลิกถูกตัดจากยอดขาย
บิลออฟไลน์ใหม่อิงเวลาที่เครื่องบันทึกตอนปิดบิล บิลเดิมที่ไม่มีเวลาขายอิงเวลาที่เซิร์ฟเวอร์รับบิล
ยอดรับชำระหนี้แสดงในหน้าลูกหนี้
รายงานใช้ต้นทุนชั่วคราวสำหรับจำนวนที่ยังขาด และใช้ต้นทุนที่จัดสรรแล้วตามใบรับเข้าหรือผลตรวจนับ
หากมีรายการที่ยังไม่ทราบต้นทุน ระบบแสดงยอดขายและพักการแสดงต้นทุนกับกำไรของกลุ่มที่เกี่ยวข้อง

ดาวน์โหลดรายงานรายวันหรือรายสินค้าจากปุ่ม CSV ในหน้ารายงาน
ไฟล์ใช้ช่วงวันที่ของรายงานที่แสดง เป็น UTF-8 พร้อม BOM เพื่อให้ Excel อ่านภาษาไทยได้
เมื่อยังไม่ทราบต้นทุน ช่องตัวเลขที่คำนวณไม่ได้จะว่าง และมีคอลัมน์สถานะต้นทุนแยกต่างหาก

## ตรวจเงินสดในลิ้นชัก

เปิด `http://127.0.0.1:8000/drawer` หรือเลือก **ตรวจเงินสด** จากเมนู
เลือกวันที่ตามเวลาไทยและบันทึกเงินทอนตั้งต้น เงินเติมหรือถอนระหว่างวันต้องระบุเหตุผล
ค่าใช้จ่ายที่บันทึกว่าจ่ายจากลิ้นชักจะถูกหักจากยอดโดยอัตโนมัติ
ให้ใช้รายการเติมหรือถอนสำหรับเงินที่ยังไม่มีรายการในระบบ เพื่อป้องกันการนับซ้ำ

ตอนปิดลิ้นชัก กรอกเงินสดที่นับได้ ระบบบันทึกยอดคาดหมายและส่วนต่าง ณ เวลาปิด
หากมีรายการเพิ่มหรือแก้ไขภายหลัง หน้าลิ้นชักแสดงยอดล่าสุดแยกจากยอดที่บันทึกตอนปิด
ยอดขายเงินสดของบิลออฟไลน์ใหม่ใช้วันขายจากเวลาที่เครื่องบันทึก
บิลที่ไม่มีเวลาขายและการรับชำระหนี้ใช้วันที่เซิร์ฟเวอร์รับรายการ
ส่วนต่างจากการแก้บิลและเงินคืนจากยอดชำระเกินนับในวันที่บันทึกการแก้บิล
ค่าใช้จ่ายนับตามวันที่ระบุในรายการ

## สำรองและกู้คืนข้อมูล

เปิด `http://127.0.0.1:8000/backup` เพื่อดาวน์โหลดฐานข้อมูลร้านเป็นไฟล์ SQLite
ไฟล์นี้รวมข้อมูลที่เซิร์ฟเวอร์บันทึกแล้ว รวมถึงบิล ลูกหนี้ ค่าใช้จ่ายและยอดปิดลิ้นชัก
เก็บไฟล์ไว้ในที่ที่เข้าถึงได้เฉพาะผู้ที่ได้รับอนุญาต

ใช้ปุ่มดาวน์โหลดบิลรอส่งแยกต่างหากบนเบราว์เซอร์แต่ละเครื่อง
เปิดหน้าขายขณะออนไลน์เพื่อเตรียมหน้า จากนั้นเลือกสำรองข้อมูลจากหน้าขายเพื่อดาวน์โหลดบิลรอส่งได้แม้ออฟไลน์
หลังอัปเดตจากรุ่นก่อน ให้ปิดแท็บหน้าขาย POS ทุกแท็บแล้วเปิดหน้าขายใหม่ขณะออนไลน์ เพื่อเตรียมหน้าสำรองสำหรับใช้ออฟไลน์
ไฟล์คิวรวมบิลที่ต้องตรวจสอบ และนำเข้าได้จากหน้าเดียวกัน
ให้นำเข้าในระบบร้านที่ตรงกับฐานข้อมูลต้นทาง เปิดหน้าขายเพื่อตรวจคิวและส่งบิลเมื่อพร้อม
ระบบใช้เลขอ้างอิงเดิมเพื่อป้องกันการบันทึกบิลซ้ำ

กู้ฐานข้อมูลลงไฟล์ใหม่และระบุไฟล์นั้นเมื่อเปิดเซิร์ฟเวอร์

```sh
python3 database_backup.py restore pos-backup.sqlite3 pos-restored.sqlite3
python3 inventory_api.py --database pos-restored.sqlite3
```

คำสั่งกู้คืนตรวจความสมบูรณ์ของไฟล์และใช้ชื่อไฟล์ปลายทางที่ยังไม่มี
หากเซิร์ฟเวอร์เดิมเปิดอยู่บนพอร์ตเดียวกัน ให้หยุดเซิร์ฟเวอร์นั้นก่อนเปิดด้วยฐานข้อมูลที่กู้คืน
หลังยกเลิกบิลค้าง ควรสำรองฐานข้อมูลอีกครั้ง เพราะการกู้คืนไฟล์ที่สร้างก่อนยกเลิกจะไม่มีบันทึกป้องกันบิลนั้น ต้องตรวจสอบบิลรอส่งจากทุกเครื่องก่อนนำกลับมาใช้
บิลใหม่ที่นำเข้าจากไฟล์สำรองคิวจะอยู่ในสถานะต้องตรวจสอบก่อนส่ง ส่วนบิลที่มีอยู่ในคิวแล้วคงสถานะเดิม การตรวจรหัสร้านและเลขบิลไม่รับประกันว่าฐานข้อมูลที่กู้คืนมีรายการหลังวันสำรองหรือบันทึกการยกเลิกครบ เจ้าของร้านต้องตรวจประวัติบิลและการรับเงินจากแหล่งข้อมูลอื่นก่อนส่งรายการนำเข้า

### ขอบเขตรุ่นทดสอบ

รุ่นนี้ใช้ SQLite ในเครื่อง บิลออนไลน์และบิลรอส่งจากรุ่นก่อนใช้กติกาสต๊อกปกติ
สินค้าที่ติดลบต้องรับสินค้าหรือปรับยอดจากการตรวจนับก่อนแก้ไขหรือยกเลิกบิลที่เกี่ยวข้อง
การทดสอบหลายอุปกรณ์จริงกับเซิร์ฟเวอร์ร่วมอยู่ในขอบเขตงานระยะต่อไป

## ทดสอบก่อนรวมโค้ด

GitHub Actions รันชุดทดสอบ Python และ Chromium บน pull request
ชุดทดสอบใช้ฐานข้อมูลชั่วคราวและไม่ต้องตั้งค่าพร้อมเพย์ของร้าน

```sh

npm ci
npx playwright install chromium
npm run test:e2e
```

ชุดทดสอบ Chromium เปิดหน้าขายด้วยสองโปรไฟล์เบราว์เซอร์

ระบบต้องเก็บทั้งสองบิลและแจ้งสต๊อกติดลบเมื่อทั้งสองโปรไฟล์ขายสินค้าหน่วยสุดท้าย

ชุดทดสอบยังตรวจการค้นสินค้า ปิดบิล และเปิดรายงานในหน้าจอสัมผัสจำลองขนาด 360 และ 768 พิกเซล
