# POS Manager

ระบบ POS สำหรับพัฒนาในเครื่อง ใช้ Python 3.10 ขึ้นไปและ SQLite

```sh
python3 -m unittest -v
python3 inventory_api.py
```

เปิดหน้าเว็บที่ `http://127.0.0.1:8000` และเก็บข้อมูลใน `inventory.sqlite3`
ใช้ `--database` เพื่อระบุไฟล์ฐานข้อมูลและ `--port` เพื่อเปลี่ยนพอร์ต

| วิธี | เส้นทาง | ข้อมูล |
| --- | --- | --- |
| GET | `/products?q=W01` | ค้นชื่อหรือรหัส แสดงหน่วยขาย ยอดคงเหลือ ต้นทุนเฉลี่ย และสถานะสินค้าใกล้หมด |
| POST | `/products` | `code`, `name`, `base_unit`, `price`, `minimum_quantity` (ไม่บังคับ) |
| POST | `/products/{id}/units` | `name`, `multiplier`, `price` |
| POST | `/products/{id}/receipts` | `unit_id`, `quantity`, `unit_cost` |
| GET | `/products/{id}/receipts` | ประวัติรับสินค้า เรียงจากรายการล่าสุด |

ส่งข้อมูล POST ด้วย `Content-Type: application/json` ต้นทุนรับเข้าเป็นราคาทุนต่อหน่วยที่เลือก
เช่น รับน้ำดื่ม 1 แพ็ก ราคาทุนแพ็กละ 120 บาท ให้ส่ง `quantity` เป็น 1 และ `unit_cost` เป็น 120
หากแพ็กมี 12 ขวด ระบบเพิ่มสต๊อก 12 ขวดในหน่วยสต๊อก

การซิงก์หลายอุปกรณ์และบัญชีเจ้าของร้านอยู่ในแผนงานถัดไป

## หน้าขาย

เปิด `http://127.0.0.1:8000/checkout` หลังเพิ่มสินค้าและบันทึกรับเข้า
เลือกสินค้าและหน่วยขาย แล้วแบ่งชำระด้วยเงินสด โอน หรือเงินเชื่อในบิลเดียว
เมื่อมีเงินเชื่อให้เลือกหรือเพิ่มชื่อลูกค้า จากนั้นเลือกพิมพ์หรือข้ามใบเสร็จได้

### QR พร้อมเพย์ตามยอดโอน

ติดตั้งไลบรารีสร้าง QR ด้วย `python3 -m pip install -r requirements-qr.txt`
แล้วกำหนดตัวแปรสภาพแวดล้อม `POS_PROMPTPAY_MOBILE` เป็นเบอร์มือถือ 10 หลัก
ที่ผูกพร้อมเพย์ของร้าน และกำหนด `POS_PROMPTPAY_NAME` เป็นชื่อร้านภาษาอังกฤษ
ความยาวไม่เกิน 25 อักขระ ก่อนเริ่มเซิร์ฟเวอร์

ระบบใส่เฉพาะยอดส่วนที่โอนใน QR เจ้าของร้านตรวจเงินเข้าด้วยตนเองก่อนยืนยัน
ก่อนเริ่มใช้งานจริง ให้สแกนตรวจสอบชื่อผู้รับและยอดที่แอปธนาคารแสดง

โครงสร้างข้อมูลอ้างอิงจาก [มาตรฐาน Thai QR Payment ของ ธปท.](https://www.bot.or.th/content/dam/bot/documents/th/our-roles/payment-systems/about-payment-systems/ThaiQRCode_Payment_Standard.pdf)

## ลูกหนี้

เปิด `http://127.0.0.1:8000/debts` หรือเลือก **ลูกหนี้** จากเมนู
เลือกชื่อลูกค้าเพื่อดูยอดค้าง บิลเงินเชื่อ และประวัติรับชำระ
เมื่อรับเงินสดหรือโอน ให้กรอกยอดที่ได้รับและเลือกวิธีชำระ
ระบบตัดยอดจากบิลเก่าที่สุดก่อน และแสดงว่าเงินถูกนำไปตัดบิลใดบ้าง

ยอดรับชำระต้องไม่เกินยอดค้างรวมของลูกค้า หากเป็นเงินโอนให้ตรวจเงินเข้าก่อนบันทึก
เมื่อขาดการเชื่อมต่อระหว่างบันทึก ให้ใช้ปุ่มส่งรายการเดิมอีกครั้ง
ระบบใช้รหัสรายการเดิมเพื่อป้องกันการบันทึกรับเงินซ้ำ

## ประวัติบิล

เปิด `http://127.0.0.1:8000/bills` หรือเลือก **ประวัติบิล** จากเมนู
เลือกบิลแล้วระบุเหตุผลเพื่อแก้ไขหรือยกเลิก ระบบเก็บบิลเดิมและคืนจำนวนสินค้าเข้าสต๊อก
เมื่อแก้ไข ระบบสร้างบิลทดแทนและตัดสต๊อกตามรายการใหม่ในคราวเดียวกัน

หากบิลเงินเชื่อเคยรับชำระ ระบบนำยอดที่รับแล้วไปตัดยอดเงินเชื่อของบิลทดแทนสำหรับลูกค้าคนเดิมก่อน
เมื่อมียอดชำระเกิน ให้เลือกบันทึกการคืนเงินจริงด้วยเงินสดหรือเงินโอน
หรือนำยอดทั้งหมดไปหักบิลค้างอื่นของลูกค้า โดยเริ่มจากบิลเก่าที่สุด
เจ้าของร้านเป็นผู้ตรวจสอบและดำเนินการรับหรือคืนเงินจริง

## ขายออฟไลน์ในหน้าขาย

เปิดหน้าขายขณะที่เชื่อมต่อเซิร์ฟเวอร์และรอให้ระบบเตรียมข้อมูลบนเบราว์เซอร์แต่ละเครื่อง
หลังจากนั้นหน้าขายใช้รายการสินค้าและลูกค้าจากข้อมูลที่เก็บไว้บนเครื่องได้
บิลที่ยังส่งไม่สำเร็จแสดงในรายการรอส่ง เมื่อเชื่อมต่อใหม่ให้เปิดหน้าขาย
เพื่อให้ระบบลองส่ง หรือกดปุ่มส่งบิลด้วยตนเอง ระบบใช้เลขอ้างอิงเดิมเพื่อป้องกันการตัดสต๊อกซ้ำ

ขณะออฟไลน์ ระบบยังสร้าง QR ระบุยอดและเพิ่มลูกค้าใหม่ไม่ได้
ใช้ QR ของร้านเมื่อต้องรับโอนและตรวจเงินเข้าก่อนยืนยัน
บิลที่ปิดขณะหน้าขายแสดงว่าออฟไลน์จะส่งผ่านเส้นทางสำหรับบิลออฟไลน์
ถ้าขายชนกับบิลอื่น ระบบเก็บทั้งสองบิลและแสดงสต๊อกติดลบที่หน้าสินค้าและสต๊อก
เมื่อรับสินค้าเข้า ระบบใช้ต้นทุนรับจริงจัดสรรให้จำนวนที่ขายเกินตามลำดับที่บันทึกบิลเข้าเซิร์ฟเวอร์
และแสดงต้นทุนที่จัดสรรแล้วในประวัติบิล สินค้าส่วนที่เหลือหลังจัดสรรจะเป็นสต๊อกพร้อมขาย
หากราคาหรือข้อมูลสินค้าเปลี่ยน บิลยังอยู่ในคิวตรวจสอบ
รายการที่ยังรอส่งอยู่กับเบราว์เซอร์เครื่องนั้น การล้างข้อมูลเว็บไซต์อาจลบรายการดังกล่าว

### ขอบเขตรุ่นทดสอบ

รุ่นนี้ใช้ SQLite ในเครื่อง บิลออนไลน์และบิลรอส่งจากรุ่นก่อนใช้กติกาสต๊อกปกติ
สินค้าที่ติดลบต้องรับสินค้าเข้าจนพ้นติดลบก่อนแก้ไขหรือยกเลิกบิลที่เกี่ยวข้อง
การปรับยอดจากการตรวจนับและการทดสอบหลายอุปกรณ์จริงกับเซิร์ฟเวอร์ร่วมยังอยู่ในขอบเขตงานถัดไป
